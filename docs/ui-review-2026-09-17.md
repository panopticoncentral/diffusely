Diffusely UI review — September 17, 2026

Diffusely has a good native foundation. The largest improvement would come from making its existing interactions predictable and its visual hierarchy calmer. Keep the artwork prominent, make saving and organizing easy to discover, and give the Mac more capable selection and inspection tools.

This is a comprehensive **source-based assessment**, covering the iOS/iPadOS and macOS branches of navigation, feeds, collections, following, tags, library and albums, media details, metadata, settings, authentication, encryption, export, and Sort Assistant. Findings describe the current working tree, including existing uncommitted edits. No application code was changed. No rendered-screen, gesture, VoiceOver, contrast, or performance validation was performed; no simulator was booted when checked. Layout risks and design proposals below are distinguished from behavior directly established by code. Line references are a snapshot and may shift as development continues.

The existing use of `NavigationStack`, native back navigation, a Mac sidebar, a real Mac Settings scene, native picker checkmarks, muted playback, Quick Look, copy commands, and explicit save-failure feedback should be preserved. Album membership rows already share a useful visual pattern with collection membership rows. The bounded media layout and use of progressive disclosure for raw metadata are also good foundations.

I would prioritize the work as follows. “Fix” denotes behavior evident in the implementation; “Improve” denotes a design recommendation; “Validate” denotes a concern requiring runtime inspection. Effort is relative, not a delivery estimate.

**1. Fix Settings presentation and dismissal.** High priority; both platforms; Fix.

Collections and Following present `SettingsView` as a sheet on both platforms. Its Mac branch is just a Form, with no Done/Close control or explicit cancellation command. Yet the app already has a native Mac Settings scene. The iOS Settings sheet also has no Done button, making dismissal dependent on the presentation gesture. Open the existing Settings window from Mac entry points, and give the iOS sheet an explicit dismissal action. Preserve the standard Command–Comma entry point. Verify opening Settings from every authentication gate and returning to the original screen. Apple describes Mac settings as a separate window, with related settings grouped into panes when necessary. [Apple: Settings](https://developer.apple.com/design/human-interface-guidelines/settings).

**2. Name the actual biometric method and clarify unlock progress.** High priority; both platforms; Fix/Improve.

Use “Use Touch ID,” “Use Face ID,” or an appropriate fallback. Hide an unavailable method or explain why it is unavailable. While unlocking, show progress as well as disabling buttons; support submitting the password from the keyboard. The existing automatic biometric attempt is useful. **3. Make deletion and storage messages match the active library.** High priority; especially Mac; Fix.

Individual and bulk delete confirmations still say items are deleted “from iCloud,” even though Mac supports a custom folder. Library detail also describes every load failure as an iCloud failure. Settings' reset warning already handles the distinction correctly. Reuse a common location-aware description for these messages. Standardize “Delete from Library” for deleting the saved file, and “Remove from Album” for changing membership. Keep the consequence that album deletion preserves its items explicit. **4. Prevent prompts from becoming permanently truncated.** High priority; both platforms; Fix.

Determine expansion from actual truncation, or use a disclosure that always permits reading the full prompt.
